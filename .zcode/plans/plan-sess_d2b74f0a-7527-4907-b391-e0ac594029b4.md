# 插件配置 Webview 表单编辑器

## 目标与范围

把现有「裸 JSON 文档」编辑器升级为 **schema 驱动的 Webview 表单**,并保留 JSON 文档作为「编辑原始 JSON」入口。主题跟随 VS Code(`--vscode-*` 变量)。

**第一版覆盖:**
- 基础类型:`string`/`text`(输入框/多行)、`int`/`float`(数字输入)、`bool`(开关)、`list`(可增删列表,元素为基础类型)
- 枚举 `options` → 下拉框(裸标量数组,见下方渲染规则)
- 嵌套 `object` → 递归分组(`items` 是 map);`list` 的 `items` 是单 schema
- `invisible` 隐藏、`description`/`hint`/`obvious_hint` 文案、`default` 预填

**第一版不做(留 TODO):** `file` 上传(需 config-files multipart 端点)、`template_list`(模板列表)、`_special`(5 种可视化选择器,需额外端点拉 provider/persona/kb 列表)、`editor_mode`/`editor_language`(未文档化值)。这些字段在表单里以「只读占位 + 提示去 JSON 模式编辑」呈现,不阻塞保存。

**JSON 模式:** 不在 webview 里做。改为侧边栏「打开插件配置」节点带两个入口——「表单编辑」(webview,默认) 和「编辑原始 JSON」(复用现有 `openPluginConfig` untitled 文档路径)。两条路都走同一个 `savePluginConfig` + 校验。

---

## 关键技术决策

### 1. Webview 资源:内联 HTML/JS,**不动 esbuild 多入口**
现有 esbuild 是单入口 Node CJS(`src/extension.ts` → `dist/extension.js`)。Webview 脚本写成 TS 模块里的**模板字符串**,HTML 在 host 端用模板拼装后 `webview.html = ...`。好处:构建管道零改动,webview 脚本仍经 `tsc --noEmit` 类型检查。代价:脚本无独立语法高亮(可接受)。

### 2. 主题:全用 `--vscode-*` CSS 变量
`<body>` 和所有控件颜色只引用 VS Code 注入的 CSS 变量(`--vscode-editor-background` / `--vscode-input-background` / `--vscode-button-background` / `--vscode-descriptionForeground` / `--vscode-errorForeground` 等),不写死任何 hex。深色/浅色/高对比度自动跟随。图标用内联 SVG 或 Unicode,不引 codicons 依赖。

### 3. 复用现有层,不重写
- API:`getPluginConfig` / `getPluginConfigSchema` / `savePluginConfig` / `reloadPlugin`(全现成)
- 校验:webview 保存时 host 调现有 `validateConfigValue`(已实现 type/options/嵌套),错误经 postMessage 回传高亮
- reloadAfterPush 策略:保存后复用现有询问逻辑

### 4. schema 渲染规则(基于调研确认的 AstrBot 自定义格式)
| `type` | 渲染 |
|---|---|
| `string` | 单行 `<input>`;有 `options` → `<select>` |
| `text` | `<textarea>` |
| `int` | `<input type=number step=1>` |
| `float` | `<input type=number step=any>`;有 `slider{min,max,step}` → `<input type=range>`(顺手做,零成本) |
| `bool` | `<input type=checkbox>` |
| `list` | 列表容器,每项按 `items`(单 schema)渲染,带增删按钮 |
| `object` | 分组容器(``),递归渲染 `items`(map) |
| `dict` | 当作 `object` 处理(核心专用,宽容) |
| `file`/`template_list`/`_special` | 只读占位:`<input readonly>` 显示当前值 + 提示「请用编辑原始 JSON」 |

`options` 是裸标量数组(非 {label,value}),`<option>` 的 label 和 value 都用该标量。

## 详细实现

### A. `src/views/configFormHtml.ts`(纯函数,易测)
导出两个东西:

```ts
/** 生成完整 webview HTML(host 注入 nonce + 初始 config/schema) */
export function configFormHtml(opts: {
    pluginName: string;
    pluginId: string;
    config: Record<string, unknown>;
    schema: ConfigSchema;
    cspSource: string;   // panel 的 Content-Security-Policy source
}): string;

/** 内联 <script> 的表单渲染逻辑(作为模板字符串,见下方协议) */
const FORM_SCRIPT = `...`;
```

HTML 结构:`<!DOCTYPE html>` + `<style>`(全 `--vscode-*` 变量) + `<body>`(表单根容器 + 底部保存/取消按钮 + 错误条) + `<script nonce>`(注入初始数据 + `FORM_SCRIPT`)。

脚本职责:
1. 读 `window.__INITIAL__`({config, schema}) → `renderForm(schema, config, root)` 递归产出 DOM
2. 用户编辑只改内存 model,不实时回写 host
3. 点「保存」→ 收集表单值为 JSON object → `postMessage({type:'save', value})`
4. 收到 `{type:'errors', errors:[{path,message}]}` → 高亮对应字段(给字段容器加 `.error` class + 滚动到第一个)
5. 收到 `{type:'saved'}` → 显示成功提示
6. 收到 `{type:'error', message}` → 显示错误条

### B. `src/views/configForm.ts`(host 端)
```ts
export async function openPluginConfigForm(
    client: AstrBotClient, workspace: PluginWorkspace,
): Promise<void>
```
逻辑:
1. `Promise.all([getPluginConfig, getPluginConfigSchema])`(失败弹错误,return)
2. `resolvePluginId(client, workspace.name)` 拿真实 pluginId
3. `vscode.window.createWebviewPanel('astrbotConfigForm', \`插件配置 - ${workspace.name}\`, ViewColumn.Active, { enableScripts:true, retainContextWhenHidden:true })`
4. `panel.webview.html = configFormHtml({...})`
5. `panel.webview.onDidReceiveMessage(msg => ...)`:
   - `msg.type === 'save'`:调 `validateConfigValue(schema, msg.value)`;有错 → `postMessage({type:'errors', errors})`;无错 → `savePluginConfig(client, pluginId, msg.value)` → 成功 `postMessage({type:'saved'})` + 按 reloadAfterPush 询问 reload;失败 `postMessage({type:'error', message: describeApiError(e)})`
   - `msg.type === 'editRawJson'`:用户点了表单里的「改用原始 JSON 编辑」→ 关闭 panel + 调 `openPluginConfig(client, workspace)`(复用 JSON 文档路径)
6. `panel.onDidDispose` 清理(无外部资源,主要是 GC)

### C. 命令接入(`commands/pluginCommands.ts`)
现有 `OpenPluginConfig` handler 改为调 `openPluginConfigForm`(表单为默认)。**命令 ID 不变**(`astrbot-devkit.OpenPluginConfig`),只是默认行为从 JSON 文档变成表单。表单内有按钮跳转 JSON 文档,保证两条路都在。

`SavePluginConfig` 命令保持不变(仍服务于 JSON 文档模式);表单模式自己处理保存,不走该命令。

### D. package.json
仅加一项 `contributes`:
```json
"webviewContentScripts": []   // 不需要
```
实际**不需要改 package.json 的 contributes**——webview panel 由命令动态创建,不声明 view。`activationEvents` 也不变。

## 协议(postMessage)

host → webview(初始化经 HTML 注入,运行时经 postMessage):
- 初始:`window.__INITIAL__ = { pluginName, pluginId, config, schema }`
- `{type:'errors', errors:[{path, message}]}`:校验失败,高亮
- `{type:'saved'}`:保存成功
- `{type:'error', message}`:保存异常

webview → host:
- `{type:'save', value: object}`:请求保存
- `{type:'editRawJson'}`:请求切换到 JSON 文档模式
- `{type:'reload'}`:请求重载插件(saved 后 host 主动处理,webview 不直接发)

## 校验与保存的复用

`validateConfigValue`(现有,`configEditor.ts:163`)对基础类型 + options + object 嵌套已完整。webview 保存时 host 端直接调它,**不重写校验**。`list` 类型校验现有 `typeMatches` 已覆盖(`case 'list': return Array.isArray(value)`)。

保存后的 `reloadAfterPush` 询问逻辑,从 `pushPluginConfig`(`configEditor.ts:127-147`)抽成一个共享函数 `askReloadAfterPush(client, pluginId, workspace)`,供表单和 JSON 两条路复用——这是唯一的小重构。

1. `npm run check-types` + `npm run lint` + `node esbuild.js --production`(全绿)
2. F5 Extension Host 冒烟:
   - 已连接服务器 + 有活跃插件 → 「打开插件配置」开 webview,字段按 schema 渲染
   - 改值 → 保存 → 成功提示 → 询问 reload

   - 切深色/浅色主题 → 表单颜色跟随

   - JSON 文档保存仍走老路径(SavePluginConfig 命令)

## 风险与权衡

- **CSP**:`panel.webview` 默认 CSP 严格,`<script>` 必须 带 nonce;样式不能用 `unsafe-inline` 以外的内联除非加 hash。用 `cspSource` 拼装,实测为主。
- **大 schema 性能**:字段极多时 DOM 渲染可能慢——第一版不优化,实测后再决定是否虚拟化。
- **list 元素是复杂类型**(如 `list` of `object`):第一版 list 只支持基础类型元素,复杂元素降级为只读 JSON 文本框(提示用 JSON 模式)。调研确认真实插件 list 多为 string。
- **主题变量覆盖度**:个别高级控件(如 range slider)的 `--vscode-*` 变量可能不全,用通用变量兜底,实测微调。
