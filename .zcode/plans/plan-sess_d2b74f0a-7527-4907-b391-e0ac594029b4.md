# 侧边栏方案 B:插件操作面板 + 本地 schema 配置 + 删 local 视图

## 目标

把侧边栏从"扁平平铺"改成"插件可展开成操作面板",每个插件下挂【配置/调试/重载/启用开关】;插件状态(已推送/已启用)从服务器批量拉取缓存到 tree;配置表单支持本地 schema(不推送也能编辑);删掉重复的 `local` 视图。

最终形态(用户确认的 mock):
```
🟢 服务器 127.0.0.1:6185 (已连接)
▾ astrbot_plugin_hello 1.0.0  (活跃)
     ⚙ 配置        ← 开表单
     ▶ 调试        ← F5 推送
     ↻ 重载        ← reload
     ☑ 已启用      ← 启用/禁用开关(服务器端状态)
▸ astrbot_plugin_xxx 2.1.0     (未推送 / 已禁用)
▸ 设置
   自动连接:开 / 调试结束后:每次询问 / 接收日志:开
📄 日志 (观察中)
```

## 改动一览

### A. `package.json` — 视图/命令/菜单
1. **删 `astrbot-devkit.local` view**(`views.astrbot` 数组去掉第二项)+ 删 `view/item/context` 里所有 `view == astrbot-devkit.local` 的菜单项(package.json:243-259,共 4 条)。
2. **新增 2 个命令声明**:
   - `astrbot-devkit.ReloadPlugin` "Reload Plugin"
   - `astrbot-devkit.TogglePluginEnabled` "Toggle Plugin Enabled"
3. **nls**:两个文件各加这两条 `"%cmd%": "..."`。
4. `localTree.ts` 文件删除。
5. **菜单**:删 local 相关 4 条;`view/item/context` 新增给 `devkitWorkspaceAction` 节点挂齿轮/调试/重载 inline 按钮(可选,主要交互靠展开节点点击)。

### B. `src/views/devkitTree.ts` — 两层化 + 新节点类型
**DevkitNode 联合类型改造:**
```ts
export type DevkitNode =
  | { kind: 'server'; ... }
  | { kind: 'workspace'; workspace; active; serverState: ServerPluginState | undefined }
  | { kind: 'workspaceAction'; workspace; action: 'config' | 'debug' | 'reload' }
  | { kind: 'workspaceEnabled'; workspace; enabled: boolean }
  | { kind: 'settingsGroup' }              // 设置分组(可折叠)
  | { kind: 'autoConnectToggle' | 'stopAction' | 'logs' | 'logsToggle'; ... }  // 收进设置组
  | { kind: 'placeholder'; ... };
// 删掉:'root'(死代码)、'pluginConfig'(被 workspaceAction.config 取代)

type ServerPluginState = { pushed: boolean; enabled: boolean; pluginId?: string };
```

**getChildren 两层化:**
```ts
getChildren(element?: DevkitNode): DevkitNode[] {
  if (!element) { return this.rootChildren(); }            // 根 → server + 插件组 + 设置组 + 日志
  if (element.kind === 'workspace') { return this.workspaceChildren(element); }  // 插件 → 4 个操作
  if (element.kind === 'settingsGroup') { return this.settingsChildren(); }      // 设置组 → 3 个开关
  return [];
}
```
- `rootChildren`:server + 每个 workspace(可折叠,CollapsibleState.Collapsed/Expanded 视活跃态)+ settingsGroup + logs。**删 pluginConfig 独立节点**。
- `workspaceChildren(ws)`:`workspaceAction(config)` / `workspaceAction(debug)` / `workspaceAction(reload)` / `workspaceEnabled`。reload 仅在 `serverState.pushed` 时显示(没推送不能 reload)。
- `settingsChildren`:autoConnectToggle + stopAction + logsToggle。

**渲染:**
- `workspace` 节点:description 显示活跃/未推送/已禁用;icon 用 `circle-large-filled/outline`;**点击 = 设为活跃(不再直接 Debug,避免误触)**;collapsible = Collapsed(非活跃)/ Expanded(活跃)。
- `workspaceAction` 节点:icon(`settings-gear`/`debug-start`/`debug-restart`)+ 点击触发对应命令(`OpenPluginConfig`/`Debug`/`ReloadPlugin`),传 workspace 参数。
- `workspaceEnabled` 节点:checkbox 风格,点击触发 `TogglePluginEnabled`,仅在 pushed 时显示。
- `settingsGroup`:icon `gear`,可折叠,默认 Collapsed。

**服务器状态缓存:**
```ts
private _serverPlugins: PluginInfo[] = [];
setServerPlugins(list: PluginInfo[]): void { this._serverPlugins = list; this.refresh(); }
/** 按插件 name 查服务器状态 */
private serverStateFor(name: string): ServerPluginState | undefined { ... }
```

### C. `src/context.ts` — 删 localTree + 加服务器状态拉取
- 删 `localTree` 字段、import、构造、`syncContext` 里的 `localTree.refresh()`。
- **新增 `refreshServerPlugins()`**:连服务器成功时调用,`listPlugins` → `tree.setServerPlugins(list)`。
- `rebuildClient` 里 client 的 `onStateChange` 回调:状态变 `connected` 时触发 `refreshServerPlugins()`(不阻塞)。

### D. `src/commands/serverCommands.ts` — Refresh 拉 server 列表
`Refresh` 命令在重连成功后追加:`await app.refreshServerPlugins()`。

### E. 新增命令(`commands/pluginCommands.ts`)
- `astrbot-devkit.ReloadPlugin`:`resolvePluginId` → `reloadPlugin` → 提示成功/失败。
- `astrbot-devkit.TogglePluginEnabled`:`resolvePluginId` → 读当前 enabled → `setPluginEnabled(_, !enabled)` → `refreshServerPlugins()` 刷新侧边栏。
- 两者都从命令参数取 workspace(跟 OpenPluginConfig 一致)。

### F. 本地 schema 配置(用户上轮选的 B)
1. **`config/scan.ts`** 新增:
   ```ts
   export function getLocalConfigSchema(dirRel: string): ConfigSchema | undefined
   ```
   读 `resolve(dirRel)/_conf_schema.json`,`JSON.parse`(容错:文件不存在/解析失败返回 undefined)。
2. **`views/configForm.ts`** `openPluginConfigForm` 改造解析顺序:
   - schema:`getLocalConfigSchema(workspace.dir)` → 有就用本地;没有再 `resolvePluginId` + `getPluginConfigSchema`。
   - config:`resolvePluginId`;能解析到 → `getPluginConfig`;解析不到(未推送)→ `defaultConfigFromSchema(schema)`(用各字段 default 预填)。
   - 保存时若 pluginId 为空(未推送):提示"该插件尚未推送,请先 F5 推送后再保存配置"(不阻塞编辑,只阻塞保存)。
3. **`views/configEditor.ts`** 老的 JSON 文档路径同步改(schema 优先本地)——抽个共享的 `resolveSchemaAndConfig(client, workspace)` 供两条路用。

## 数据流(关键)

**服务器状态拉取时机(用户确认:连接/刷新时批量拉):**
1. `Refresh` 命令 → 重连成功 → `refreshServerPlugins()`
2. client `onStateChange` → `'connected'` → `refreshServerPlugins()`(静默,失败不报错)
3. `TogglePluginEnabled` / `ReloadPlugin` 后 → `refreshServerPlugins()`(即时刷新)

**配置 schema 解析顺序(B 方案):**
本地 `_conf_schema.json` > 服务器 schema > 空 schema(渲染空表单)

## 风险与权衡

- **插件点击语义改变**(从"直接 Debug"变成"设为活跃"):是有意为之(避免误触),但改变现有 muscle memory。调试改由展开后的【调试】子项触发。这是方案 B 的核心交互取舍。
- **服务器状态缓存可能过时**:只在连接/刷新/操作后拉,期间服务器端手动改了启用状态侧边栏不知道。可接受(用户可手动 Refresh),不引入轮询。
- **两层 tree 的 expand 状态管理**:VS Code 默认保留 collapsibleState,但如果 `refresh()` fire `undefined` 会重新渲染。第一版不主动管理展开态,接受展开态可能被刷新重置(实测后必要时再用 `TreeItemExpandedState` 优化)。
- **本地 schema 解析用 `JSON.parse` 不容忍注释**:AstrBot 的 `_conf_schema.json` 是纯 JSON(无注释),够用;如要容忍,复用 io.ts 的 stripJsonc(要导出)。
